Slide 5 Keypoint 1: Past Updates
Past Updates: Dual-Track Doctor Profiling Workflow
Strict alignment with ERPNext HCP Profile Submission WF: 0-bottleneck processing for verified doctors.
Track A: Existing Doctor ('Existing HCP')
  • Selection: MedRep selects existing doctor from verified national masterlist.
  • Action Applied: 'Submit for Processing' (doc.profile_action == "Existing HCP").
  • State Transition: Directly transitions to PROCESSED.
  • Zero Manager Bottleneck: REQUIRES NO MANAGERIAL APPROVAL. Eliminates administrative delays for verified doctors.
  • Automatic Direct Sync: Instantly syncs preferred features into HCP Masterlist and links local program HCP Account.
Track B: New Doctor ('+ Add New Doctor')
  • Selection: MedRep enters new doctor details (PRC ID, Name, Specialty, Clinic).
  • Action Applied: 'Submit for Approval' (doc.profile_action == "New HCP").
  • State Transition: Enters PENDING APPROVAL state.
  • Manager Review: Scoped to District Sales Manager (DSM) queue for validation.
  • DSM Approval: Clicks 'Approve' → State: APPROVED → Committed to Masterlist.
  • DSM Rejection: Selects rejection reason → MedRep edits and resubmits.
Speaker Notes
"Our past workflow alignment solved major field friction: if a doctor already exists in our masterlist, MedReps don't wait for managers—it transitions to Processed instantly. But if it's a completely new doctor, it safely diverts to Pending Approval for DSM review, protecting our universal masterlist from invalid or duplicate entries."

Slide 7 Keypoint 2: Present Updates
Present Updates: Zero-Deletion & ERPNext Role Alignment
Continuous modify/resubmit flow and backend workflow authorization parity.
🛡️ Zero Deletion Guarantee (V.0.4.6)
  • Removed 'Discard' Button: MedReps cannot accidentally discard or delete proposed facilities from their submission list.
  • Continuous Modify & Resubmit: Rejected facilities exclusively present 'Modify & Resubmit'. Reps can update name, address, or region and resubmit continuously.
  • No SFE Rejection Deletion: Removed 'Reject & Delete Resubmission' branch. SFE rejections simply mark status as 'Rejected' with reason, preserving the facility record.
  • Decoupled Service Layer: rejectInstitution no longer calls deleteInstitution.
⚙️ ERPNext Role & Workflow Parity (V.0.4.5)
  • Problem Resolved: Fixed ERPNext HTTP 417: Not a valid Workflow Action on SFE rejection.
  • Role Alignment: Assigned explicit Sales Force Effectiveness role to active SFE account (lesantos@pims-marketing.com).
  • Multi-Role Transitions: Updated Institution WF rules to allow Sales Force Effectiveness, System Manager, and Sales Manager on both Approve and Reject actions.
  • Client Fallback & CSRF: Added CSRF verification and direct PUT update fallback.
🏷️ Rejection Remarks Display Isolation (V.0.4.4)
Submissions in Approved, Processed, or Pending Approval states previously showed misleading red rejection remark banners because timeline comments were mapped indiscriminately. In V.0.4.4, strict conditional gating ensures only submissions that actually underwent rejection display the red rejection card.
Speaker Notes
"Slide 7 highlights our two major backend and workflow hardening updates: In V.0.4.6, we eliminated the discard and deletion options for proposed institutions, ensuring MedReps can continuously modify and resubmit without data loss. In V.0.4.5, we fixed the ERPNext workflow role mismatch that caused rejection failures, ensuring seamless approval and rejection across all manager personas."

Slide 9 Keypoint 3: Future Updates
Future Updates: Mobile Enhancements (Tabs & Ergonomics)
Implementing user-requested tab restructuring, hidden views, and mandatory fields (Part 1).
1. Consent Tab Last
  • User Request: "Consent must be display at the last of the tab."
  • Target Sequence: 1. Doctor Info → 2. Questionnaire → 3. Consent.
  • Ergonomics: Aligns with the natural chronological flow of medical sales visits.
2. Hidden 'Others' Tab
  • User Request: "Others tab must be hidden."
  • Streamlined UI: Eliminates low-utility tab from submission and wizard views.
  • Visual Ergonomics: Saves horizontal screen width and avoids tab overflow.
3. Continuous GPS
  • User Request: "Geolocation should be active all the time."
  • Always-Active: Keeps GPS service active during profiling sessions.
  • Smart Matching: Auto-prioritizes nearby hospitals with geo-timestamps.
4. Mandatory Legend
  • User Request: "Legend of mandatory field in Doctor's Information."
  • Top Banner: Clear banner: "* Indicates required fields for profiling submission".
  • Zero Guesswork: Fast and clear form completion for field reps.
Speaker Notes

Third, making Geolocation always active for continuous location awareness. Fourth, adding a clear legend of mandatory fields in Doctor's Information."
