1. Exact Code Locations for Environment Switching

A. HCP Profiling Mobile App (Flutter)

The mobile app centralizes environment selection in lib/app_config.dart. The ApiService and all screens consume this configuration dynamically.

// File: lib/app_config.dart (Lines 14-24) class AppConfig { static AppMode mode = AppMode.hcp; // =========================================================================== // 🚀 SERVER ENVIRONMENT SWITCH (SINGLE-LINE TOGGLE) // Change to Environment.production when ready to deploy: // =========================================================================== static Environment environment = Environment.development; // <--- CHANGE HERE! // Development Server URL static const String devServerUrl = 'https://dev.pmii-marketing.com'; // Production Server URL (Configured for live ERPNext) static const String prodServerUrl = 'https://pmii-marketing.com'; /// Dynamically returns the active server URL static String get serverUrl => environment == Environment.production ? prodServerUrl : devServerUrl; }

To switch the Mobile App to Production:

  1. Open lib/app_config.dart.
  2. Change line 17 from static Environment environment = Environment.development; to:
    static Environment environment = Environment.production;.
  3. If your production URL is different from https://pmii-marketing.com, update prodServerUrl.

B. Territory Reconfiguration Web App (Python Server)

The server powering the Territory Reconfiguration Web App supports both code-level toggling and zero-code environment variable overrides.

# Files: scratch/serve_portal.py & installers/Territory_Reconfiguration_App/server.py # =========================================================================== # 🚀 SERVER ENVIRONMENT SWITCH (SINGLE-LINE TOGGLE) # =========================================================================== ENVIRONMENT = os.environ.get('ENVIRONMENT', 'development').lower() # <--- TOGGLE DEV_SERVER_URL = 'https://dev.pmii-marketing.com' PROD_SERVER_URL = 'https://pmii-marketing.com' ERPNEXT_SERVER_URL = os.environ.get( 'ERPNEXT_URL', PROD_SERVER_URL if ENVIRONMENT == 'production' else DEV_SERVER_URL )

To switch the Web App to Production:

  • Option 1 (Code Edit): Change 'development' to 'production' on line 20 of server.py.
  • Option 2 (Zero-Code PowerShell Command):
    $env:ENVIRONMENT="production"; python server.py
  • Option 3 (Custom Production URL via CLI):
    $env:ERPNEXT_URL="https://prod.pmii-marketing.com"; python server.py

2. Architectural Proof: Why Switching to Production Will NOT Break Workflows

Enterprise systems frequently experience failures during production cutovers due to schema drift, hardcoded strings, or authentication mismatches. The HCP Profiling App and Territory Web App are completely shielded from these failure modes by five structural safeguards:

Failure Mode Standard System Behavior Our Built-In Fail-Safe Protection
1. ERPNext REST API Contract Custom endpoints break across server environments. Standard Frappe v15 Compliance: All API requests target canonical Frappe resources (/api/resource/HCP, /api/resource/HCP Account, /api/resource/Medical Institution, /api/resource/HCP Profile Submission). Dev and Prod share identical contracts.
2. Workflow State Transitions Hardcoded status strings cause workflow deadlocks. 1:1 Workflow Alignment: Existing HCP routes directly to Processed without manager approval; New HCP routes to Pending Approval. The app respects Frappe server workflow transition expressions identically.
3. Database Schema Drift Missing fields or null values crash JSON parsers. DataSanitizer Schema Immunity: In lib/services/data_sanitizer.dart, every model parses through null-coalescing and defensive type coercion. Any added/missing DocType fields in production are safely absorbed without crashing.
4. Dynamic URL Resolution Hardcoded development URLs cause mixed-content leaks. Zero Hardcoded URLs: Every screen (including detail_screen.dart and self_service_qr_screen.dart) dynamically binds to AppConfig.serverUrl. No dev URLs persist after switching.
5. Web App State Preservation Server reboots erase work in progress. Client-Side Single-Page Architecture: The Territory Reconfiguration portal runs in-browser with localStorage snapshotting. Switching backend endpoints only alters sync destinations, leaving territory hierarchies completely intact.
