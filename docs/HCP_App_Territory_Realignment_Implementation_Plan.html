1. Executive Summary & Core Engineering Objectives

Commercial pharmaceutical programs (Bayer Consumer Health, Abbott Diabetes Care, RiteMed, etc.) frequently restructure territories. These reorganizations involve renaming territory codes (e.g., RM106 → RM107), shifting district boundaries, merging sales teams, or reassigning field medical representatives.

Without an automated realignment engine, complex server-side territory updates break field workflows, cause permission lockouts for District Sales Managers (DSMs), and result in orphaned doctor masterlists.

The 4 Non-Negotiable System Guarantees:
  • 1. Zero Profiling Disruption: Field representatives are never blocked from profiling doctors or saving local drafts during server re-alignment.
  • 2. Zero DSM Approval Lockouts: District Sales Managers can seamlessly approve in-flight submissions created under old/renamed codes without permission errors.
  • 3. Zero Orphan Doctor Accounts: Existing HCP Account doctor affiliations automatically migrate in-place without generating duplicate records.
  • 4. Enterprise Complex Data Resilience: Capable of ingesting >1,000 to 10,000+ nodes via recursive auto-pagination and resolving deep N-tier hierarchies.

5. End-to-End Realignment Workflow Sequence

Step Actor / Stage Action Executed Data Integrity Assurance
Step 1 ERPNext Admin Territory tree restructured in /app/territory (e.g., RM106 renamed to RM107). Server database updated.
Step 2 MedRep Phone Rep opens app or switches program. App detects cache expiry via TTL. Fresh territory hierarchy downloaded.
Step 3 Profiling Wizard resolveUserTerritory() detects RM106 is obsolete → auto-heals to RM107. Zero rep blockage; draft saved with new active code.
Step 4 In-Flight Submission DSM evaluates pending submission created before cutover under RM106. Inheritance logic verifies rep ownership → No 403/417 lockout.
Step 5 DSM Approval DSM clicks Approve. App auto-upgrades submission territory to RM107. Submission state transitions to Approved.
Step 6 HCP Account Sync syncHcpAccount() updates existing doctor record in-place via PUT. Zero duplicate doctor accounts; specialty & clinics preserved.

6. Standard Operating Procedure (SOP) on Cutover Day

Cutover Execution Checklist:
  1. Pre-Cutover (T - 24 Hours): Advise DSMs to clear high-priority submissions in Pending Approval.
  2. ERPNext Tree Update (T - 0 Hours): Reconfigure territories in /app/territory and update Sales Person hierarchy.
  3. Server Migration Script: Execute scratch/erpnext_territory_realignment_migration.py to batch-update existing doctor accounts.
  4. Client Sync: Field reps log in or tap refresh; app automatically fetches new tree via TTL freshness.
  5. Verification: Perform dual-role test (MedRep profiling + DSM approval) confirming zero lockouts.
